从 PayloadsAllTheThings 到个人知识库：维护自己的渗透 Cheatsheet 体系

2026-09-02·3 min read
#知识管理#方法论#渗透测试

PayloadsAllTheThings、InternalAllTheThings、HackTricks……这类公开 Cheatsheet 项目是渗透测试者的公共图书馆。但三年下来我发现：用得最多的不是收藏最全的，而是自己整理过的。这篇聊聊如何把公共资源内化成个人知识体系。

收藏夹的陷阱#

看到好文章 star 一下、好 payload 复制进笔记——这个动作产生的是"仓库"而不是"知识库"。区别在于：仓库按来源组织（哪来的），知识库按使用场景组织（什么时候用）。实战时你脑子里的问题是"这个场景怎么破"，而不是"上周看到的那篇文章在哪"。

我的目录结构：按攻击面组织#

个人知识库的顶层结构跟随 MITRE ATT&CK 的思路，按战术阶段组织，再往下按具体技术分：

pentest-notes/
├── 01-recon/            # 信息搜集
│   ├── subdomain.md
│   ├── fofa-recipes.md  # 我的常用查询语句集
│   └── ...
├── 02-initial-access/   # 边界突破
├── 03-web/              # Web 漏洞利用
│   ├── sqli-payloads.md
│   ├── ssrf-bypass.md   # 每次实战补充新绕过手法
│   └── ...
├── 04-ad/               # 内网与 AD
├── 05-postex/           # 后渗透
├── 06-defense/          # 蓝队视角与检测规则
└── templates/

两个设计决策：

  1. 单文件单主题：一个文件讲透一类问题，文件名即检索入口
  2. 06-defense 和攻击笔记平行存在：每次研究攻击手法，强迫自己补一行"防守方怎么看"——这既是知识完整性，也是做报告时的降维优势

笔记模板：为实战检索设计#

每篇笔记用统一模板，重点是"检索友好"：

# SSRF 绕过手法

## 适用场景
目标有 SSRF 点位，但存在黑名单/解析限制

## 手法清单
| 场景 | payload/思路 | 备注 |
| --- | --- | --- |
| 过滤 127.0.0.1 | 十进制/八进制 IP 变体 | 2025-XX 实战验证 |
| 过滤内网段 | DNS rebinding | 需要可控解析 |

## 已验证记录
- 2025-XX 项目 A：十六进制绕过成功，附当时的请求/响应

## 参考
- PayloadsAllTheThings#ssrf

"已验证记录"是最有价值的段落——公共 payload 和"我验证过能用"之间隔着一个授权项目的距离，这部分只可能来自自己的积累。

更新机制：以项目为单位回收#

每做完一个项目（或 CTF、或复现一篇文章），强制做一次"回收"：

  1. 本次用到的手法，回填到对应笔记的"已验证记录"
  2. 走了弯路的地方，写成"此路不通"条目——负知识同样值钱
  3. 公共项目里发现的新手法，摘录进自己的体系，标注来源链接

没有项目输出的空窗期，就定期同步上游公共项目的更新，相当于 git pull 自己的知识库。

工具选型：越朴素越持久#

我的答案可能让人失望：Markdown 文件 + Obsidian（或纯 VS Code）+ Git 同步。理由：

  • 纯文本可 grep：grep -r "rebinding" pentest-notes/ 比任何 GUI 搜索都快
  • Git 天然版本化：哪个项目补充了什么手法，历史一目了然
  • 不依赖任何在线服务：笔记里常有敏感信息（目标特征、验证记录），绝不能放在第三方云端笔记里

知识库的敌人不是工具不够好，而是三年后放弃维护。所以结构越简单、越贴近文件系统，它活得越久。
