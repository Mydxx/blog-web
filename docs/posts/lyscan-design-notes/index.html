写一个目录扫描器：Lyscan 设计笔记

2026-08-20·4 min read
#工具开发#Python#渗透测试

目录扫描（dirsearch、ffuf、gobuster）是渗透测试的标配动作，轮子已经很多，但我还是自己写了一个——用造轮子的方式把这些工具的设计吃透，是最快的学习路径。这篇是设计笔记。

核心问题：并发模型#

扫描器本质是"高并发 + 低超时 + 快速失败"的 HTTP 客户端。Python 下首选 asyncio + aiohttp：

import asyncio
import aiohttp

async def probe(session, url, semaphore):
    async with semaphore:          # 并发上限由信号量控制
        try:
            async with session.get(
                url, timeout=aiohttp.ClientTimeout(total=8),
                allow_redirects=False,
            ) as resp:
                return url, resp.status, resp.headers.get("Content-Length")
        except (asyncio.TimeoutError, aiohttp.ClientError):
            return url, 0, None    # 网络错误标记为 0，与 404 区分

async def scan(targets, concurrency=50):
    sem = asyncio.Semaphore(concurrency)
    async with aiohttp.ClientSession() as session:
        tasks = [probe(session, t, sem) for t in targets]
        return await asyncio.gather(*tasks)

并发数不是越大越好：50 并发对小站可能直接把服务打挂（扫描器变 DoS 器，大忌），对 CDN 站点又太慢。默认 30，按响应延迟自适应调整，是我现在的做法。

另外务必 allow_redirects=False：301/302 要单独看 Location 指向，自动跟随会让"所有路径都 302 到首页"的站点刷出一屏假阳性。

字典策略：分层而不是一把梭#

一个设计错误是所有目标都跑同一份大字典。我的分层：

层级内容时机
快速层常见管理路径、备份文件、.git/.env 等敏感点每个目标必跑
技术层按指纹选字典（检测到 PHP 用 php 字典，ASP 用 asp 字典）指纹确认后
扩展层大字典暴力仅深测时

技术层的字典选择可以自动化：先发一个 / 和一个随机路径，从响应头、报错页面推断技术栈，再决定加载哪份字典。

软 404：误报过滤是 scanners 的良心#

最大的误报来源是软 404——服务器对不存在的路径返回 200 + 自定义错误页。过滤思路：

1. 基线对比。扫描前先请求一个几乎不可能存在的随机路径（如 /d0-Not-Exist-9x/），记录其状态码和响应特征，结果与基线一致的直接丢弃：

def is_soft_404(resp, baseline) -> bool:
    if resp.status == baseline.status and \
       resp.length == baseline.length:
        return True
    # 长度有 ±64 字节抖动的（动态令牌），做相似度比对
    if abs(resp.length - baseline.length) < 64:
        return similarity(resp.body, baseline.body) > 0.95
    return False

2. 按状态码分组去重。同一响应长度 + 同一状态码出现超过阈值（比如 20 次），大概率是"万能 200"配置，整组标灰而不是逐条列出。

3. 内容摘要而非精确长度。只比 Content-Length 会被动态时间戳骗过，对可疑组取 body 的模糊哈希再比对一次。

结果输出：为人服务，不是为机器#

扫描输出最终是给人看的，我给自己定的输出规范：

  • 结果按 2xx 手动验证 > 3xx 看跳转 > 带敏感特征的 4xx 分级
  • 每条结果附"为什么值得看"（如：备份文件特征、管理路径命名）
  • 支持输出 JSON 供后续工具链消费，人读的 HTML 报表是渲染层的事

合规提醒#

目录扫描对目标是有实际压力的行为。只对书面授权的目标使用，控制并发，工作时间跑，发现把服务打挂的迹象立即停止。工具能力和授权边界，永远一起讲。

造完这个轮子，最大的收获是看懂了 dirsearch 和 ffuf 的配置项为什么长那样——每一个开关背后都是一类误报场景。
